# Third-Party Notices

Echora's own source is proprietary/source-available (see [LICENSE](./LICENSE)).
It bundles or invokes the third-party components below. This file is a
living document — see `docs/adr/0006-third-party-licensing-and-bundling.md`
for the reasoning behind the bundling strategy. This is not legal advice;
professional legal review is recommended before wide distribution.

Status: **Fase 3 (Media Integration) validated the real sidecar chain in
dev** (search → resolve → mpv playback, live, with actual audio). Exact
pinned versions/checksums for the *shipped* artifact, and the portable
mpv build itself, are finalized in Fase 8 (Packaging) — see
`docs/adr/0007-arm64-native-ci-and-mpv-build.md`.

**Update (2026-09-01) — the three items below are resolved:**
1. mpv's GPL-2.0+ text, yt-dlp's Unlicense + GPLv3+ (`THIRD_PARTY_LICENSES.txt`,
   covering the standalone binary's bundled Readline), Deno's MIT notice, and
   Rust MPL-2.0 dependencies' license text are all embedded directly into
   Echora's compiled binary (`include_str!`, same pattern as
   `docs/adr/0008`'s bundled `moods.json` — see `src-tauri/src/licenses.rs`)
   and reachable in-app via Settings → Third-Party Licenses. Baked in at
   compile time, so it's present regardless of `.deb`/AppImage packaging
   details — no `tauri.conf.json` `resources` entry needed for this part.
2. The `cargo-about`/`cargo-deny` and npm license-checker audit promised
   above has run against the real dependency tree — see the two tables
   below.

**Update (2026-09-06) — the `.so` bundling blocker above is resolved,**
and the mpv binary's own FFmpeg is now built from source, minimal, and
bundled with OpenSSL (Apache-2.0) as its TLS backend instead of the
distro's monolithic shared FFmpeg — see the new **FFmpeg**/**OpenSSL**
rows below and `docs/adr/0007-arm64-native-ci-and-mpv-build.md`'s
2026-09-06 update for the full reasoning, real before/after size
measurements, and the licensing analysis behind the OpenSSL-over-
Mbed-TLS/GnuTLS choice. ARM64 was also dropped from the build/release
matrix the same day (no ARM users) — every "x86_64, aarch64" mention
below now reads "x86_64 only."

## Bundled sidecar binaries

| Component | Role | License | Distribution form | Obligation |
|---|---|---|---|---|
| **mpv** | Audio-only playback, spawned as a subprocess, controlled via its JSON IPC socket (`--input-ipc-server`). Never linked into Echora's binary. Validated in dev with the distro package (0.37.0); the shipped artifact instead builds mpv from source in CI (see ADR 0007) — not this distro package. | GPL-2.0-or-later (unmodified upstream build) | Built by Echora's own CI (x86_64 only as of 2026-09-06 — ARM64 dropped, see ADR 0007), bundled as a relocatable binary + its runtime `.so` dependencies (rpath `$ORIGIN`). | Ship mpv's own license text; do not modify the binary; point to mpv's public source for the exact version built. Safe as "mere aggregation" per the GPL FAQ — see ADR 0001 and 0006. |
| **FFmpeg** | Decodes the audio stream mpv is handed (`libavcodec`/`libavformat`/`libavfilter`/`libavdevice`/`libswresample`/`libswscale`), and the RMS-metering (`astats`) filter behind the orb's audio reactivity. Never linked into Echora's own Rust binary — only ever loaded by the mpv subprocess above. Not the distro's package: built from source, minimal (`--disable-everything` plus only the specific decoders/demuxers/protocols/filters Echora's playback path needs — see `scripts/build-ffmpeg.sh`), replacing what used to be Ubuntu's monolithic shared FFmpeg (see ADR 0007's 2026-09-06 update for the full "why" and real before/after size measurements). | LGPL-2.1-or-later (`--enable-gpl`/`--enable-nonfree`/`--enable-version3` never passed — see ADR 0007 for why `--enable-version3` specifically was evaluated and rejected: it would have been required to link Mbed TLS, which is why this build uses OpenSSL instead) | Built by Echora's own CI (x86_64 only, see above) from the exact tag pinned in `scripts/build-ffmpeg.sh` (`FFMPEG_VERSION`), bundled as `.so` files alongside mpv, same rpath scheme. | Ship FFmpeg's LGPL-2.1 license text; do not modify the source; point to FFmpeg's public source for the exact version built. Corresponding-source obligation (LGPL §6) now falls on Echora directly, not by transitivity through a distro package — every release uploads the exact pinned tag, an unmodified source mirror, and the exact `./configure` line used as release assets (`ffmpeg-provenance-<arch>.txt`, `ffmpeg-source-<arch>.tar.gz`, both generated by `scripts/build-ffmpeg.sh` itself, never hand-copied). |
| **OpenSSL** | TLS backend FFmpeg's `https` protocol uses to fetch the resolved audio stream URL (mpv itself does the fetching — yt-dlp only resolves the URL, never proxies bytes). Never linked into Echora's own Rust binary. | Apache-2.0 (OpenSSL 3.x) | Built as a build-time dependency of the FFmpeg build above (system `libssl-dev` at build time), bundled as a runtime `.so` alongside FFmpeg's own libraries, same rpath scheme. | Ship OpenSSL's Apache-2.0 license/copyright notice. Chosen over Mbed TLS (also nominally Apache-2.0, smaller) specifically because Mbed TLS forces FFmpeg's own `--enable-version3` (upgrading the whole FFmpeg build to LGPL-3.0-or-later) per FFmpeg's own build-time license gate — OpenSSL does not, under this build's `--disable-gpl` configuration — see ADR 0007 for the real, verified reasoning. GnuTLS was also rejected (GPL/LGPL-3.0-licensed GMP dependency, same style of forced escalation). |
| **yt-dlp** | Resolves/searches YouTube media, spawned as a subprocess. Never linked into Echora's binary. Validated in dev at version `2026.08.19` (official `yt-dlp_linux` standalone binary, SHA-256 checksum-verified against the release's `SHA2-256SUMS`). | Source: Unlicense. **Official standalone Linux binary release is GPLv3-or-later as a combined work** (bundles GNU Readline into the frozen CPython interpreter). | Official standalone binary from yt-dlp's GitHub Releases (`yt-dlp_linux`; `yt-dlp_linux_aarch64` no longer bundled, ARM64 dropped 2026-09-06 — see ADR 0007), unmodified, checksum-verified. | Ship yt-dlp's GPLv3 license text and its own `THIRD_PARTY_LICENSES.txt`; do not modify the binary; point to yt-dlp's public source/release for the exact version bundled. |
| **Deno** | JS runtime required by yt-dlp's EJS mechanism (YouTube anti-bot/signature challenges), invoked by yt-dlp itself via `--js-runtimes deno:<path>`. Validated in dev at version `2.9.6` (official release zip). | MIT | Official prebuilt `deno` binary, unmodified, checksum-verified. | Ship Deno's MIT license/copyright notice. |
| **PO-Token provider** (e.g. `bgutil-ytdlp-pot-provider`) | Would supply YouTube PO-Tokens to yt-dlp. **Not currently bundled or needed** — plain Deno via `--js-runtimes` resolved all public-video test cases in Fase 3 without one. Revisit only if resolution failures in the wild indicate YouTube is enforcing PO-Tokens for the videos Echora needs. | N/A — not shipped | N/A | If ever added: confirm its license, and prefer its Deno mode over Node to avoid bundling a second JS runtime. |

## Notes

- No component above is statically linked or FFI-linked into Echora's own
  Rust binary; all are invoked as separate OS processes. See
  `docs/adr/0001-mpv-sidecar-not-libmpv.md` and
  `docs/adr/0006-third-party-licensing-and-bundling.md` for why this
  matters for keeping Echora's own source proprietary.
- If any future dependency cannot be bundled under these conditions, that
  conflict will be documented here and resolved (or the dependency
  dropped) before release — not hidden.
